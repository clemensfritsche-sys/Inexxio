# Phase 2, Schritte 2.3–2.5: Kommunikation skalierbar · Notiz an jedem Datensatz · ein Verlauf

Projektakte `docs/konzept/lernende-firma.md` §4.2. Branch `claude/phase2-verlauf`, Migration 168.

## Was

- **2.3 Kommunikation skalierbar.** `messages.topic` (das Anliegen) als Spalte mit Index
  `(topic, at)`; gesetzt nur vom Modell mit dem Betreff (`Message._topic`). Die Migration füllt
  sie **in Python** mit einer eingefrorenen Abschrift von `domain.topic` – SQL kennt `casefold`
  nicht («ß» → «ss»); ein Test vergleicht beide. «Beantwortet» ist EINE SQL-Bedingung
  (`communication._ANSWERED`), gelesen von `answered` (eine Liste) und `open_counts` (alle, die
  an uns gehen); `_state` bleibt die eine Regel für offen/überfällig. Der Verlauf kommt in Seiten
  (`communication.page`, Cursor Zeit · Nummer, Rundschreiben ohne Zustand einmal je Gruppe).
- **2.4 Notiz an jedem Datensatz.** `message_parties.object_id` statt `person_object_id`
  (Zwei-Deploy-Regel: alte Spalte ungemappt, `NOT NULL` weg, Brücken-Trigger bis zum Drop,
  `PENDING_DROP` + Backlog). Kanal `note` (nie offen, nie hinaus). `move_note`: Vermerk am
  falschen, Inhalt mit Verweis am richtigen Datensatz, nichts gelöscht.
- **2.5 Ein Verlauf.** `GET /erp/history/{nummer}` (ersetzt `GET /erp/messages`), eine
  Komponente `components/erp/history.tsx` an Person, Firma, Auftrag, Artikel, Instanz, Dokument.

| Was | vorher | nachher |

| Seite des Verlaufs (Mitarbeiter, ~2'500) | – | 24 ms |

## Verworfen

- **Backfill in SQL** (`lower(regexp_replace(…))`): `lower` ≠ `casefold`; das Anliegen hiesse vor
  und nach der Migration verschieden.
- **Die erste SQL-Fassung von «beantwortet»** (Join auf `user_profiles` je Zeile): der Planer
  schätzte die Kosten auf 1.5 Mio. – PostgreSQL schaltete JIT samt Optimierung ein (580 ms von
  640 ms). Mit `WITH staff AS MATERIALIZED` schätzt er richtig (64'000, kein JIT). Wächst der
  Bestand stark, kommt JIT wieder in Reichweite (`jit_above_cost` 100'000) – dann `jit` für die
  Datenbank prüfen.
- **`documents`/`document_refs` aus dem Verlauf ausschliessen**: sie stehen im Log an der Nummer
  des Dokuments, nicht am Datensatz, an dem es hängt – dort sind sie seine eigenen Änderungen.
